# QuantForge V0.1 工程化审查与整改

## 基本信息

- 日期：2026-09-26
- 类型：Refactor / Docs / Test / Chore
- 影响范围：项目架构与工程文档、类型标注、核心代码可读性、测试可靠性及开发工具配置。
- 对应提交：`e2619f3626fdb5c52752c8db892f0b4b36b69147`（`feat: 基础框架`）

## 变更背景

V0.1 首轮架构审查发现 README 和架构文档仍描述旧 Demo 或 `src/quant` 布局，与仓库真实的根目录 `quant/` 包不一致。测试中有重复定义的方法会覆盖前一个同名测试，测试也通过手动修改 `sys.path` 导入源码。项目缺少统一的 Ruff/Mypy 配置和关键交易规则注释，增加后续维护与审查成本。

## 变更内容

- 重写架构文档以反映当前实现，说明 V0.1 不含 RiskManager，并修正包目录描述。
- 补全 README 的实际能力、运行方式、执行时间语义、限制和文档入口。
- 扩展 AGENTS.md 的架构、类型、注释、测试与文档要求。
- 配置 pytest、ruff、mypy 开发依赖和项目规则。
- 为核心领域、成交成本、账户更新、Engine 生命周期和绩效公式补充必要的中文说明。
- 将 `PendingOrder.quantity` 标注为可选，匹配末日买入意图没有执行价格时的实际语义。
- 修正 DataFeed 迭代器类型；移除 Engine 中不可达的待处理订单收尾映射。
- 删除被同名方法覆盖的重复测试，并移除测试对 `sys.path` 的手动注入。
